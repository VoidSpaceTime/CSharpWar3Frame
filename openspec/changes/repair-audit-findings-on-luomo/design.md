## Context

框架使用 ECS 保存运行时语义，Native 层投影副作用，OOP 负责模板及编排。审查已用精确 Friflo 3.6.0 和原样源码复现问题；11 个既有场景中 Item companion 场景失败。当前仅有治理 spec，其他六个活跃提案不能自动视为已实施。

## Goals / Non-Goals

目标是让正常路径和失败路径满足一致的可验证契约。消除错误归属、时间记账、阶段传播及数据转换，而不是吞异常、跳过断言或返回伪造结果。

不实现新的 War3 Native API、地面物品模拟、UI 控件树、同步队列、Pause 合成、复活/池化及新的远程攻击模式；不改 C++/CLI ABI。已有原生调用的参数、顺序和职责错误仍在修复范围。

## Decisions

### 时间与系统执行

调度保留两个独立量：距离下个调度点的余量、尚未交付的真实经过时间。达到间隔时交付一次实际 delta，交付量清零，调度余量用于维持频率。Immediate 保持每 tick；改变间隔明确重置策略。不得把已交付余量再次算入。

空间索引在现有位置回写后、搜索前注册，使用统一时序。未实现 ItemCreateNativeSystem 的占位不作为活跃系统；保留 TODO 与请求类型供以后功能使用，避免默认系统树运行不可用能力。

Buff tick 按真实时间推进且不越过存活区间；续期撤销失效阶段标记；Once 首次命中立即记录消耗、迭代后回收。属性创建使用所属实体 Store，避免局部测试/多 Store 的跨库链接。技能升级通过共用施法参数写入入口重算，避免创建与升级双份定义。

### 目标与归属

单位阵营由现有 ECS 玩家归属和联盟位解析，建立唯一领域查询入口，Aura/UnitHelper/TargetFilter 复用。Self 独立，未知归属不当敌人，明确 Ally/Enemy/Neutral。原生类型/魔免数据未建模时保留 Native 识别 TODO；不在规则层调用原生 API。

AuraOwner 统一表达光环归属；清理、查询、移除同样使用该关系。Buff 目标反查沿 ModifyTarget → AttrOwner，按当前有效目标集合执行集合差异更新，避免重复贡献与离场残留。多光环来源的归属不得互相窃取。

### 现有 Native 投影

联盟缓存从最终 bits 派生。SetAlliance 切换时清 Neutral；取消 Neutral 后恢复 Basic 所表达的关系，Helper 与 Native 使用同一转换规则。

特效变换脏时由累计状态重建约定 XYZ 顺序的矩阵，随后正确重放缩放；首次同步和增量同步共用应用函数。句柄注销先于原生销毁。保留 Compare-Sync / Dirty-Driven / Request 的分工，不为了形式统一迁移所有字段。

### 编译期注册

使用符号所属程序集区分框架与消费者：框架继续生成自身 partial 注册实现；消费者生成本程序集内部的 ProjectTemplateRegistration.Initialize，调用公共 Register。先初始化框架，后注册项目，成功后才置幂等标记。零模板消费者也有空入口。

类型使用 FullyQualifiedFormat，字符串使用 Roslyn literal API，排序 Ordinal。新增定位到声明的诊断，避免反射/ModuleInitializer 的不可控时机与 AOT 扫描。只修模板跨程序集；外部 SystemRegister 不允许绕过统一 order 排序追加到末尾，未支持输入给明确诊断。

demo/test 显式引用 Analyzer，业务启动前调用固定入口；New 复制 demo 后无需根据项目名修改 registrar。不削弱存活校验以迁就错误测试夹具。

### 实体身份

token 使用不含外层消息分隔符的版本化格式，携带 ID 和 revision。解析检查格式、范围、Store、存活及代次；过期、畸形或旧格式均拒绝，不能降级为裸 ID。与待审同步批处理/context 断言独立。

### 构建与资源

引入职责单一的进程执行器：参数列表、并发排空两个输出流、有限日志尾部、超时/取消和退出码。编排严格按准备 → publish → 产物检查 → pack → 可选启动推进，错误中止后续阶段。multi N 定义为额外启动 N 个，N 必须为正；启动次数有界，不杀用户已有进程。

保留 BuildDstPath 与写入 callback 的绝对路径，只把最终 w3x 写入同目录 staging 文件，验证成功后替换。失败不清理游戏插件、不删除有效地图。WE 解包与回同步全部成功后才删除 .we。非缓存按文件集同步新增、修改、删除，不以目录时间代表文件版本。

资源方法参数按签名绑定，保留默认值/命名参数；转换代码进入构建专用目录并通过编译输入替换原清单，源清单不变。二次构建输出确定，失败不写半转换文件。加载图配置写回原目标 INI。模型缓冲区以独立容量字段管理分配/扩容/释放，Dispose 幂等；ModelFormat 尊重输入并在非交互执行时退出。

## Alternatives

- 单纯捕获默认系统树异常会隐藏启动失败；采用不注册未实现能力。
- 把项目模板编入框架破坏项目边界；只给 consumer 加 Analyzer 又不能跨程序集 partial；采用显式 registrar。
- 反射自动发现增加 AOT/初始化风险；采用编译期符号生成。
- 重命名整个构建目录会破坏 callback 的绝对模块路径；采用最终文件原子替换。
- 修改 Assets API 默认值迎合转换器错误会改变用户契约；按原签名生成。
- 延迟 Once 删除之外再忽略重复结果仍会执行副作用；首次命中消耗策略。

## Migration Plan

1. 提案、设计、delta 和任务先入 Git；依据用户直接实施/提交授权记录范围。
2. 增加 SDK 回归宿主，按运行时基础、领域/同步、生成器、构建、资源工具分批实现及验证，提交只包含该批文件。
3. 新 token 发送接收同版本更新，重新启动游戏会话；旧格式不兼容，不做静默回退。Aura 归属按新会话重新创建，无需存档迁移。
4. 与 fix-ability-level-cast-phase-rebuild 重叠逻辑完成并验证后，将旧提案标记已取代并引用本 change；其余待审功能保持原状态。
5. R3 复核、summary、官方 archive 合并新增规格，再提交归档。原 ECS-Framework 分支保持不变，不 push。

回滚用分批反向提交，不 reset/rebase 既有历史。依赖提交按逆序撤回；同步协议及发送/接收同时回滚并重启会话。外部临时 SDK/缓存不进入 Git。

## Risks / Trade-offs

- Native 调用记录只能证明参数/顺序，不能证明客户端视觉与多人锁步 → summary 明确非阻塞集成缺口。
- 新 token 不兼容旧客户端 → 显式版本拒绝，避免错投实体。
- 管理代码编译不代表 AOT/宿主通过 → SDK JIT publish 为阻塞，AOT/客户端结果单列。
- 外部系统注册不属于本次模板修复 → 明确诊断，不追加越过事件清理边界。
- 资源清单生成方式影响 MSBuild 输入 → 真正 SDK 构建及脚手架隔离副本验证，不能仅做字符串测试。
